# Calibration Specification

## 1. Overview
เพื่อคงมาตรฐานของการเป็นระบบ IRT 3PL อย่างแท้จริง ข้อสอบทุกข้อที่จะถูกใช้จริงใน Adaptive Test ต้องผ่านกระบวนการเทียบมาตรฐาน (Calibration) หาค่า a, b, c parameters เสียก่อน ห้ามการมโนค่าตัวเลขเองโดยเด็ดขาด

## 2. Question Lifecycle (Item Status)

วัฏจักรของข้อสอบแต่ละข้อจะมีสถานะ (Status) ดำเนินไปตามนี้:

1.  **DRAFT** (ร่างข้อสอบ)
    *   ครูสร้างข้อสอบในระบบ พร้อมระบุ Domain, เฉลยที่ถูกต้อง และโครงสร้าง
    *   ข้อสอบยังไม่ถูกใช้งานใดๆ
2.  **EXPERT_REVIEW** (ตรวจสอบโดยผู้เชี่ยวชาญ)
    *   ผู้เชี่ยวชาญตรวจสอบเนื้อหา ความถูกต้อง และความเที่ยงตรงเชิงเนื้อหา (Content Validity)
3.  **PILOT** (สอบนำร่อง)
    *   ข้อสอบถูกนำไปให้กลุ่มตัวอย่างทดลองสอบ (โดยยังไม่นำคะแนนไปคิดผล)
    *   ระบบจะต้องบันทึก Response (0,1) เอาไว้จำนวนมาก
4.  **CALIBRATION** (กำลังเทียบมาตรฐาน)
    *   เมื่อมีข้อมูลครบกำหนด (เช่น Sample Size > 200) ข้อสอบถูกล็อค และเข้าสู่กระบวนการคำนวณทางสถิติเพื่อหา Parameter
5.  **CALIBRATED** (ผ่านการเทียบมาตรฐานแล้ว)
    *   ได้ค่า $a$ (Discrimination), $b$ (Difficulty), $c$ (Guessing) และ Standard Error ของ Parameter กลับมา
6.  **ACTIVE** (เปิดใช้งาน)
    *   ข้อสอบถูกบรรจุเข้า Item Bank (Operational Item)
    *   **เฉพาะข้อสอบในสถานะ ACTIVE เท่านั้นที่จะถูกดึงไปใช้ใน CAT Session จริง**

## 3. Mock Mode สำหรับการพัฒนา (Development & Demo)

เนื่องจากในขั้นตอนพัฒนาระบบซอฟต์แวร์ เราอาจจะยังไม่มีข้อมูลจากนักเรียนจริง 200-500 คนมาทำ Pilot ระบบจะอนุญาตให้ใช้ตัวแปร `USE_MOCK_IRT=true` ในไฟล์ `.env.local`

**กติกาสำหรับ Mock Mode:**
*   ระบบจะทำเครื่องหมายและกำหนดค่าพารามิเตอร์จำลอง (Simulation Parameters) ให้อัตโนมัติ (เช่น a=1.2, b=0.5, c=0.25) เพื่อให้ CAT Engine ทำงานได้
*   UI ของระบบฝั่งนักเรียนและครู **ต้อง** แสดงแบนเนอร์หรือป้ายกำกับชัดเจนว่า **"DEVELOPMENT / SIMULATION MODE"**
*   ห้ามนำผลคะแนน หรือพารามิเตอร์จากโหมดนี้ไปอ้างอิงเป็นผลการวิจัยโดยเด็ดขาด
